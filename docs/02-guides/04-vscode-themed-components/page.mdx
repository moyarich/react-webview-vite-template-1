# VS Code-Themed Components

All webviews share the same component and theme layer under:

```text
src/webviews/shared/
├── components/
└── styles/
```

## Private theme tokens

React components do not read `--vscode-*` variables directly.

The shared stylesheet maps optional VS Code host values into app-owned private tokens with browser defaults:

```css
:root {
  --webview-foreground: var(--vscode-foreground, #1f2328);
  --webview-background: var(--vscode-editor-background, #ffffff);
  --webview-panel-border: var(--vscode-panel-border, #d0d7de);
  --webview-button-background: var(--vscode-button-background, #0969da);
  --webview-button-foreground: var(--vscode-button-foreground, #ffffff);
}
```

Components consume only the private layer:

```tsx
className="bg-[var(--webview-button-background)] text-[var(--webview-button-foreground)]"
```

The dependency direction stays one-way:

```text
shared React components
→ --webview-* tokens
→ browser defaults
→ optional VS Code theme values
```

## Why share the component layer?

Dashboard and Settings should not duplicate buttons, cards, theme mappings, or accessibility behavior.

A new webview can reuse the same shared components immediately.


## CSS composition

Shared theme and base styles are split into:

```text
src/webviews/shared/styles/
├── tokens.css
└── base.css
```

`tokens.css` defines the private theme variables.

`base.css` imports Tailwind and the shared tokens, then applies common document styles.

Each webview may also define local CSS:

```text
src/webviews/dashboard/dashboard.css
src/webviews/settings/settings.css
```

The entry point chooses its style composition explicitly:

```tsx
import "../shared/styles/base.css";
import "./dashboard.css";
```

This supports three patterns cleanly:

```text
shared only
shared + local
shared + additional shared modules + local
```

The important rule is that reusable components depend on the private `--webview-*` tokens, not directly on VS Code host variables.
