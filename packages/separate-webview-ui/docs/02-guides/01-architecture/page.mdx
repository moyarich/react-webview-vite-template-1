# Architecture

This template keeps the VS Code extension and webview UI in separate package directories.

## Root extension package

The repository root contains the extension host:

```text
package.json
vite.extension.config.ts
tsconfig.json
src/extension.ts
```

It runs in Node.js inside the VS Code extension host and can use the `vscode` module.

## Nested webview package

The browser application lives under:

```text
webview-ui/
```

It has its own:

- `package.json`
- lockfile
- Vite config
- TypeScript configs
- React source

This package runs in a browser context and cannot import the `vscode` module directly.

## Runtime boundary

```text
Root extension
    │
    │ panel.webview.onDidReceiveMessage(...)
    │
    ▼
VS Code APIs

React webview
    │
    │ acquireVsCodeApi().postMessage(...)
    │
    ▼
Extension host
```

The package separation makes this runtime separation visible in the filesystem.

## Build outputs

```text
dist/
└── extension.js

webview-ui/dist/
├── index.html
└── assets/
    ├── index.js
    └── index.css
```

The extension references the built browser assets through `webview.asWebviewUri(...)`.


## Command surface

The extension contributes one command:

```text
react-webview-vite.openPanel
```

It is available from the Command Palette, from the editor context menu, and from the Explorer file context menu:

```text
React Webview
└── Open React Webview
```

The submenu is declared with `contributes.submenus` and inserted into `editor/context` through `contributes.menus`.

The submenu itself then receives the command through a menu whose ID matches the submenu ID:

```json
{
  "submenus": [
    {
      "id": "react-webview-vite.webviewMenu",
      "label": "React Webview"
    }
  ],
  "menus": {
    "editor/context": [
      {
        "submenu": "react-webview-vite.webviewMenu"
      }
    ],
    "explorer/context": [
      {
        "submenu": "react-webview-vite.webviewMenu"
      }
    ],
    "react-webview-vite.webviewMenu": [
      {
        "command": "react-webview-vite.openPanel"
      }
    ]
  }
}
```


### Editor vs Explorer context menus

VS Code uses different menu contribution points depending on where the user right-clicks:

```text
Right-click inside an open editor
→ editor/context

Right-click a file in the Explorer sidebar
→ explorer/context
```

If a command should appear in both places, contribute the submenu to both menu IDs.
